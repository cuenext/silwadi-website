# Silwadi SEO, Human Copy & Local Growth Design

**Date:** 2026-08-22  
**Project:** Dr. Munir Silwadi Dental Centre website  
**Primary launch domain:** `https://silwadi.ae/`  
**Fallback domain:** `https://silwadidentalcentres.ae/`

## Goal

Turn the current multi-page redesign into a credible, high-converting dental website that feels written by a strong healthcare team rather than generated by a template, while building a technically clean foundation for local and organic search in Abu Dhabi.

The work must improve three things together:

1. **Human trust and conversion** — shorter, clearer, more natural patient-facing copy and stronger visual hierarchy.
2. **Local search authority** — consistent branch information, location pages, local signals, structured data and stronger treatment/doctor relationships.
3. **Technical SEO quality** — metadata, canonicals, sitemap, robots, schema, internal linking, performance and crawlability.

This design extends the approved multi-page hospital-style architecture. It does not replace it.

---

## Core Principles

### Patient-first writing

High-level pages should be concise. Detailed SEO content belongs on the page that answers the search intent.

Avoid:
- cutting-edge
- state-of-the-art
- world-class
- exceptional / unmatched / best-in-class claims
- personalised solutions tailored to your unique needs
- repeated “multidisciplinary clinical workflows” language
- keyword stuffing
- long paragraphs that repeat the heading
- generic healthcare filler
- guarantees or implied outcomes

Prefer:
- short headings
- concrete statements
- simple clinical language
- specific services, doctors, locations and next steps
- a calm, confident institutional voice

### Search engines do not get a separate website

SEO improvements must strengthen the patient experience. No hidden blocks, doorway pages, city-name repetition or low-value long-form content written only to hit word counts.

### Claims must be supportable

Do not invent awards, ratings, accreditations, patient counts, treatment success rates, insurance coverage, technology ownership, parking details or branch opening information.

### One canonical domain setting

The build targets `silwadi.ae`, but domain-specific SEO values must be easy to switch later. Canonical URLs, schema URLs, sitemap URLs and Open Graph URLs should be generated from one central site-origin value or an equivalent controlled replacement mechanism.

If the clinic keeps `silwadidentalcentres.ae`, the content and page architecture remain unchanged; only domain-specific SEO values are switched.

If a domain migration happens after launch, preserve URL paths where practical and implement a one-to-one 301 redirect map from old URLs to new URLs.

## Patch Sequence

The SEO/content rebuild is intentionally split into seven implementation patches: **Patch 6 through Patch 12**.

### Patch 6 — Human Copy, Visual Trust & Locations

**Purpose:** Remove the AI/template feel before layering deeper SEO on top.

#### Homepage changes

Reduce text density and make the page behave like a hospital-quality entry point rather than an explainer page.

Target structure:
1. Hero
2. compact trust row
3. four treatment pathways
4. doctor/team proof
5. short About teaser
6. short Digital Dentistry teaser
7. Locations teaser
8. consultation CTA

Hero language remains concise. One sentence of supporting copy is enough.

#### Replace bland “12 doctors” treatment

Do not present `12 doctors` as a generic isolated stat card.

Preferred presentation:

**12 dentists & specialists**  
*One established clinical team.*

Support visually with a restrained overlapping/linear strip of real supplied doctor portraits and a `Meet the team` link. Keep specialty labels secondary and avoid badge clutter.

`Since 1980` remains the strongest heritage signal.

#### Human-copy pass

Rewrite Home, Doctors, About, Digital Dentistry, Treatments, Dental Implants and Contact to:
- shorten headings and intros;
- remove repeated explanatory paragraphs;
- use patient language rather than internal clinical/process language;
- preserve necessary clinical caution on treatment pages;
- keep useful detail where it supports patient decisions or search intent.

#### Locations page

Create `locations.html`.

**Bani Yas Tower** is the active location and includes:
- branch name;
- exact verified address;
- phone;
- verified opening hours;
- email/contact route;
- directions action;
- responsive map embed;
- consultation CTA;
- insurance guidance only where verified;
- parking guidance only if verified.

**Al Raha Mall** is clearly labelled `Coming Soon` and must not be represented as an operating branch in local-business structured data until open.

All existing `#locations` navigation links move to `locations.html`.

### Patch 7 — Local SEO Foundation

**Purpose:** Make local relevance explicit and consistent without keyword spam.

#### NAP normalization

Create one canonical Name / Address / Phone representation for the active branch and apply it consistently across:
- header/utility areas where shown;
- footer;
- Contact;
- Locations;
- structured data;
- metadata where relevant.

#### Local signals

Use natural Abu Dhabi location context in:
- homepage title/meta;
- Locations page;
- Contact page;
- core service pages;
- doctor profiles where the clinician works at the branch.

Do not repeat `dentist Abu Dhabi` unnaturally in body copy.

#### Map and service area context

Locations/Contact can contain the responsive map and concise location context. The site should not invent a precise service-area radius.

---

### Patch 8 — Technical SEO Infrastructure

**Purpose:** Build the crawl/index/structured-data layer once and consistently.

#### Central SEO origin

Add a single project-level source of truth for:

`https://silwadi.ae`

Implementation may be a small generation script/config file or a controlled static replacement system, but domain-specific values must not be manually scattered without a documented switch procedure.

#### Per-page metadata

Every indexable page gets:
- unique `<title>`;
- unique meta description;
- one clear H1;
- canonical URL;
- Open Graph title/description/url;
- appropriate robots directive;
- meaningful internal links.

#### Structured data

Use only schema types that accurately describe the content.

Core graph can include:
- `Dentist` for the operating dental business/location;
- `Organization` / website identity where helpful;
- `BreadcrumbList` on internal pages;
- `Person` for doctor profile pages when fields are verified;
- service-related structured data only when it accurately reflects visible page content.

Do not add self-serving aggregate rating/review markup solely to manufacture search-result stars.

Al Raha must not be published as an open LocalBusiness while it is still coming soon.

#### Crawl files

Create:
- `robots.txt`
- `sitemap.xml`

Sitemap contains canonical absolute URLs for indexable production pages only.

#### Canonical behavior

Preferred URLs use clean `.html` paths for the current static architecture unless a later hosting layer explicitly supports rewrites. Avoid duplicate URL variants.

- Orthodontics / Braces
- Cosmetic Dentistry

Then expand to:

#### Service-page template

Each page should include only useful sections:
1. concise search-intent hero;
2. what the treatment/care area is;
3. who may need it / common reasons for consultation;
4. what assessment or treatment planning may involve;
5. relevant doctors;
6. relevant location/contact route;
7. short FAQs where they answer real patient questions;

Avoid fixed treatment promises, prices, timelines or suitability claims unless verified and appropriate.

#### SEO targeting

Titles/H1s can use Abu Dhabi naturally where high-intent local relevance is useful. Body copy should remain human.

Internal-link pattern:

`Treatment → relevant doctor → consultation/location`

and

`Doctor → relevant treatment → consultation/location`

### Patch 11 — Performance & Mobile Conversion

**Purpose:** Improve real mobile experience and Core Web Vitals while preserving the premium visual system.

Work includes:
- explicit image dimensions/aspect ratios;
- correctly sized doctor images where possible;
- lazy loading for below-the-fold imagery;

Performance work should improve real loading rather than chase a synthetic score at the expense of design or accessibility.

## Homepage Content Budget

The homepage must not become an SEO article.

Guideline:
- hero support copy: about 15–30 words;
- treatment cards: one short sentence each;
- doctor section: names/specialties, minimal supporting copy;
- About teaser: roughly 30–60 useful words;
- Digital teaser: roughly 25–50 useful words;
- location teaser: operational facts, not promotional paragraphs;
- one final consultation CTA.

If a paragraph does not help a patient choose, trust, navigate or act, remove it.

---

## Visual Content Rules

- Fewer bordered cards.
- More whitespace and editorial grouping.
- Use real doctor photography as trust evidence.
- Do not cover faces with badges or text overlays.
- Keep teal as an accent, not a decorative effect everywhere.
- Reduce repeated stat boxes.
- Avoid fake device/technology illustrations unless real clinic photography becomes available.
- Keep motion subtle and nonessential.

---

## SEO Content Rules

- One page = one primary intent.
- Never create near-duplicate location/service pages just to target keyword variants.
- Use synonyms naturally rather than repeating an exact phrase.
- Answer common patient questions directly in headings where useful.
- Link treatment pages to relevant clinicians and vice versa.
- Keep emergency-care language clear but never imply 24/7 availability unless verified.
- Do not claim Invisalign specifically unless the clinic confirms it offers that brand; use orthodontics/aligners/braces language according to verified services.
- Do not publish review/rating schema unless it meets current search-engine eligibility rules and is genuinely supported by visible, valid review content.

## Domain Switch Strategy

### Preferred launch: `silwadi.ae`

All production canonicals, sitemap URLs and structured-data `url`/`@id` values use `https://silwadi.ae/`.

### If the clinic keeps the old domain before launch

Change the central site origin to:

`https://silwadidentalcentres.ae`

Then regenerate/update:
- canonicals;
- Open Graph URLs;
- schema URLs/IDs;
- sitemap URLs.

No page copy, layout or internal relative navigation needs to change.

### If the domain changes after indexing

Implement one-to-one permanent redirects, preserve equivalent paths where possible, update all canonical/structured/sitemap references, submit the new sitemap and keep redirects in place long term.

## Testing Strategy

Each patch uses contract tests before production changes.

Tests should cover:
- required files/pages;
- one H1 per page;
- expected human-copy constraints;
- no banned filler phrases where practical;
- internal links and asset existence;
- consultation routing;
- NAP consistency;
- location status;
- canonical/meta/schema presence;
- sitemap/robots content;
- schema JSON parsing;
- domain-switch consistency;
- doctor/treatment cross-links;
- no broken local URLs;
- JavaScript syntax;
- local HTTP smoke tests.

Before moving each patch to `main`, the patch branch must be fast-forwardable and freshly verified.

## Success Criteria

The completed site should:
- feel noticeably less AI-written and less text-heavy;
- make doctors, treatments, locations and consultation paths obvious within seconds;
- use `Since 1980` and real clinicians as stronger trust proof than generic stat cards;
- provide useful dedicated landing pages for high-intent dental searches;
- expose consistent verified local business information;
- have clean canonical, sitemap, robots and structured-data infrastructure;
- remain easy to switch between `silwadi.ae` and the old domain;
- remain dependency-light and compatible with the existing local preview workflow;
- avoid unsupported medical or marketing claims;
- preserve the approved premium hospital/private-clinic visual direction.
